# Spotify Model

- **Layer / Taxon:** operating · execution
- **Layer:** ⚠️ conflict — Gemini Execution; ChatGPT Alignment. *Filed under Execution per master; layer disputed — kept `layer: execution`.*
- **Origin** `[FACT/SIGNAL]`: Henrik Kniberg & Anders Ivarsson, Spotify, 2012 whitepaper. Kniberg later warned he *did not invent a universal "Spotify model."* [source: https://blog.crisp.se/2015/06/07/henrikkniberg/no-i-didnt-invent-the-spotify-model]
- **Structure:** `Squad (autonomous cross-functional) → Tribe (related squads) → Chapter (horizontal specialists for standards) → Guild (voluntary community).`
- **SWOT:** **S** in high-trust cultures, scaling without losing velocity · **W** a snapshot Spotify itself abandoned; Chapter dual-reporting; Tribe silos · **O** extract the *principles* (autonomy + alignment), don't copy the *structure* · **T** renaming departments "Tribes" without changing command-and-control.
- **Case study:** **ING Bank** adopted it at scale, then pivoted to **LeSS** because Squads created rigid silos. **Cautionary — Spotify itself:** autonomy without alignment → fragmented codebase; "aspirational, not descriptive." ⚠️ *Adjudication: Gemini asserts Spotify "abandoned" the model as flat fact; ChatGPT is more careful — present as "Spotify moved away from it," not a clean documented abandonment.* [source: https://www.adaptws.com.au/ing-improves-on-the-so-called-spotify-model-using-less/]
